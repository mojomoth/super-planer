# Super Planer PoC

게임 기획자를 위한 워크플로우 시각화 서비스의 PoC 세 개입니다. Next.js 16(App Router) + SQLite(`node:sqlite`)로 만들었고, 세 앱이 SQLite 파일 하나를 같이 씁니다.

```
질문하기(step1) ──워크플로우로 열기──▶ 워크플로우(workflow-view) ──기획서 만들기──▶ 기획서(plan-doc)
      /                                    /workflow                                /plan
```

| PoC | 폴더 | 주소 | 하는 일 |
|---|---|---|---|
| 1. 질문하기 | `step1` | http://localhost:3100/ | 대충 쓴 게임 아이디어에 소크라테스식 질문을 하나씩 던지고, 다 답하면 게임 이름(가제)과 ELI5 형식 컨셉을 보여 줘요. |
| 2. 워크플로우 | `workflow-view` | http://localhost:3100/workflow | n8n처럼 카드와 연결선으로 된 캔버스. 카드를 펼치면 에이전트 대화 세션이 보이고, 에이전트 답마다 OpenAI로 만든 예시 이미지가 한 장 붙어요. 답변 속 URL과 이미지는 슬라이드/격자 미리보기로 보여요. |
| 3. 기획서 | `plan-doc` | http://localhost:3100/plan | 동결된 결정과 이미지 예시를 골라 Markdown 기획서를 만들고, 이미지를 포함한 Markdown 미리보기로 보여 줘요. |

각 앱은 예시 데이터가 들어 있어서 따로 열어도 바로 볼 수 있어요.

## 실행

```bash
cd pocs
npm run dev                         # 세 앱을 한 번에: http://localhost:3100 (/, /workflow, /plan)
LLM_PROVIDER=mock npm run dev       # LLM 없이 정해진 답으로
PORT=3500 npm run dev               # 다른 포트로 (앱은 PORT+1~+3)
npm run build && npm start          # 운영 모드 (next start)
```

`serve.mjs`가 세 앱을 `127.0.0.1`의 PORT+1(질문하기), +2(워크플로우), +3(기획서)에 띄우고, PORT(기본 3100)에서 경로로 나눠 보내요: `/workflow`와 `/workflow/…`는 워크플로우, `/plan`과 `/plan/…`는 기획서, 나머지는 질문하기. 브라우저는 3100 하나만 열면 돼요. `BASIC_AUTH_USER`와 `BASIC_AUTH_PASSWORD`를 둘 다 넣으면 `/healthz`를 뺀 모든 경로에 HTTP Basic 로그인을 걸어요(둘 다 비우면 로그인 없음, 하나만 넣으면 켜지지 않아요). 로그인과 상관없이 다른 사이트에서 보낸 쓰기 요청(GET·HEAD가 아닌 요청)은 403으로 막아요(브라우저가 붙이는 `Sec-Fetch-Site` 기준, CSRF 방지). 앱 하나가 죽으면 나머지도 끄고 0이 아닌 코드로 끝나요.

`npm run dev -w step1`처럼 앱 하나만 띄울 수도 있지만(질문하기 3101, 워크플로우 http://localhost:3102/workflow, 기획서 http://localhost:3103/plan), 그러면 다른 앱으로 가는 링크는 열리지 않아요.

Node 24가 필요해요(`pocs/.node-version`, `engines`). 의존성은 `pocs/node_modules`에 이미 설치돼 있어요. nvm 기본 node가 다르면 `nvm use 24`로 바꾸거나 Homebrew node를 앞에 두세요(`export PATH=/opt/homebrew/bin:$PATH`).

### LLM 선택

`lib/llm.ts`가 아래 순서로 고르고, 화면 오른쪽 위에 `LLM: <이름>`으로 보여 줘요.

| 조건 | 사용하는 것 |
|---|---|
| `ANTHROPIC_API_KEY`가 있으면 | Anthropic API, 기본 `claude-opus-5-5` (`LLM_MODEL`로 변경). 정책상 거절되면 서버 쪽 기본 대체 모델이 같은 요청을 다시 처리해요(`fallbacks: 'default'`). 한 번 시도는 5분에서 끊고, 실패하면 한 번만 다시 시도해요 |
| 없으면 | 로컬 `claude` CLI (로그인된 Claude Code 사용, `LLM_CLI_MODEL`, 기본 `sonnet`, `LLM_TIMEOUT_MS`, 기본 120000) |
| `LLM_PROVIDER=mock` | LLM 없이 정해진 질문·답변·문서 조립 |

`LLM_PROVIDER=anthropic|claude-cli|mock`으로 강제할 수 있어요. LLM 호출이 실패하거나 규칙에 안 맞는 답을 주면 자동으로 mock 결과로 대신하고, 화면에 그 사실을 작게 적어 둬요. `LLM_DISABLE_CLI=1`이면 CLI를 건너뛰고 mock으로 가요.

### 이미지 생성 (OpenAI)

OpenAI Images API(`POST /v1/images/generations`, 1536x1024 webp)로 실제 이미지를 만드는 곳은 두 군데예요. mock 대체가 없어서 `LLM_PROVIDER=mock`이어도 OpenAI만 써요.

- 기획서 '이미지 예시' 패널의 "이미지 만들기"
- 워크플로우 에이전트 답변: 답 하나에 예시 이미지 한 장(`/workflow/api/images/<id>`)을 붙여요. LLM이 그릴 장면을 한두 문장으로 적고, mock이나 LLM 실패 때는 카드 제목과 설명, 보낸 메시지로 프롬프트를 만들어요(질문하기에서 가져온 카드의 설명은 질문이라 빼요). 동결 결정 요약에는 만들지 않아요. 키가 없거나 만들기에 실패하면 이미지 없이 답과 참고 링크가 오고, 그 이유가 `예시 이미지: …` 한 줄로 붙어요.

Next는 앱 폴더의 `.env.local`만 읽어요. 로컬에서는 키를 `pocs/plan-doc/.env.local`과 `pocs/workflow-view/.env.local`에 넣거나(`.env.*`는 gitignore 대상), `OPENAI_API_KEY=sk-... npm run dev`처럼 환경 변수로 넘기고 서버를 다시 켜세요. 배포에서는 환경 변수 `OPENAI_API_KEY`로 넣어요.

```bash
# pocs/plan-doc/.env.local, pocs/workflow-view/.env.local
# 필수. 없으면 기획서 폼에 안내가 뜨고 "만들기"가 꺼지며, 워크플로우 답에는 이미지가 붙지 않아요
OPENAI_API_KEY=sk-...
# 선택 (아래는 기본값). BASE_URL은 테스트 스텁을 붙일 때만 바꿔요
OPENAI_IMAGE_MODEL=gpt-image-2.5-flare
OPENAI_TIMEOUT_MS=180000
OPENAI_BASE_URL=https://api.openai.com/v1
```

한 장 만들 때마다 OpenAI 사용료가 나가고, 수십 초 걸릴 수 있어요. 워크플로우 대화는 답 하나가 LLM 답변과 이미지 만들기를 차례로 기다려서, 기다리는 동안 "답을 쓰고 예시 이미지를 만드는 중이에요."가 보여요. 만든 파일은 업로드 이미지와 같은 업로드 폴더(아래 '데이터')에 저장돼요. 워크플로우 예시 데이터의 .jpg 이미지(`workflow-view/public/samples/`)는 같은 API로 한 번 만들어 저장소에 넣어 둔 것이라, 예시를 다시 넣을 때는 OpenAI를 부르지 않아요.

### 데이터

- DB: `pocs/.data/super-planer.db` (WAL). `SUPER_PLANER_DB=/경로/파일.db`로 바꿀 수 있어요.
- 업로드·생성 이미지: DB 파일 옆 `uploads/` (기본 `pocs/.data/uploads/`, `SUPER_PLANER_DB=/tmp/x.db`면 `/tmp/uploads/`). 워크플로우 에이전트 이미지는 `wf_images`, 기획서 이미지는 `plan_inputs`에 기록돼요.
- 이 사이트 안의 이미지 주소는 앱 경로를 붙인 루트 기준 주소로 저장해요(`/workflow/samples/…`, `/workflow/api/images/<id>`, `/plan/samples/…`, `/plan/api/images/<id>`). 예전 DB에 남은 `http://localhost:3102/…`, `/samples/…`, `/api/images/…`는 앱이 켜질 때 한 번 새 주소로 고쳐요.
- 초기화: 서버를 끄고 `rm -rf pocs/.data` 후 다시 실행하면 예시 데이터부터 새로 만들어요.

## 배포 (Render)

웹 서비스 하나로 세 앱을 한 주소에 올려요(`/`, `/workflow`, `/plan`).

| 설정 | 값 |
|---|---|
| Root Directory | `pocs` |
| Build Command | `npm ci --include=dev && npm run build` |
| Start Command | `node serve.mjs` (`npm start`와 같은데, npm 프로세스가 없어서 메모리를 덜 써요) |
| Health Check Path | `/healthz` (로그인 없이, 세 앱이 다 뜨면 `200 ok`, 그 전에는 `503`) |
| 환경 변수 (이름만) | `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `BASIC_AUTH_USER`, `BASIC_AUTH_PASSWORD`, `NODE_VERSION=24` |

- Render가 주는 `PORT`에서 프록시가 받고, 앱 셋은 그 뒤 PORT+1~+3에서 돌아요.
- `BASIC_AUTH_PASSWORD`는 20자 이상의 무작위 ASCII로 넣어요. 로그인 실패 횟수 제한이 없어서 비밀번호 강도에 기대고, 한글처럼 ASCII가 아닌 글자는 입력 방식(NFC/NFD)에 따라 로그인이 안 될 수 있어요.
- `ANTHROPIC_API_KEY` 없이 배포할 때는 `LLM_PROVIDER=mock`을 넣어요. 안 넣으면 헤더에 `LLM: claude-cli`가 보이고, 호출마다 `claude` 실행이 실패한 뒤 mock으로 가요.
- 메모리: 운영 모드에서는 `serve.mjs`가 앱 셋을 `--max-semi-space-size=2`로 띄워요(메모리 약 25~30MB 절약). macOS에서 잰 세 앱과 프록시의 메모리 합(footprint)은 `node serve.mjs` 기준으로 첫 화면을 연 뒤 약 220MB, 질문하기 → 워크플로우 → 기획서 흐름을 한 번 돈 뒤 약 285MB였어요. 큰 업로드와 이미지 만들기를 한꺼번에 몰아 보낸 점검에서는 최고 약 405MB였어요. Linux에서 직접 재지는 못했어요. 512MB를 넘으면 Render가 서비스를 다시 켜고, 그때 데이터도 지워져요.
- Render의 Edge Caching은 켜지 마세요. 켜면 `/_next/static/…`처럼 `public` 캐시 헤더가 붙은 파일이 로그인 없이 캐시에서 나갈 수 있어요.
- Free 플랜은 디스크가 임시예요. 다시 배포하거나 재시작하거나 쉬다가 깨어나면 DB와 업로드·생성 이미지가 모두 지워지고, 앱이 예시 데이터를 다시 넣어요. 내려받은 .md 속 이 사이트 이미지 주소도 그때 깨져요.

## HIL 체크리스트

`LLM_PROVIDER=mock`으로 먼저 한 번, 그다음 실제 LLM(CLI 또는 API 키)으로 한 번 해 보는 걸 권해요. LLM을 쓰면 질문 하나에 30초쯤 걸릴 수 있어요. 세 앱 모두 `npm run dev` 뒤 http://localhost:3100 에서 열어요.

### 1. 질문하기 (http://localhost:3100/)

- [ ] 첫 화면에 아이디어 입력칸, 예시 버튼 4개, 오른쪽에 최근 세션 목록(예시 세션 1개 포함)이 보인다.
- [ ] 세 글자 이하로 보내면 "네 글자 이상 적어 주세요."가 뜬다.
- [ ] 예시 "좀비가 나오는 편의점에서 하룻밤 버티기"로 시작하면 첫 질문이 "…결국 뭘 하는 게임인가요?" 같은 '이 게임은 무엇인가' 질문으로 나온다.
- [ ] 질문마다 한 문장짜리 질문, 쉬운 비유 힌트(게임·폰·SNS·학교 비유), 보기 3~5개, "잘 모르겠어요, 추천해 줘", 직접 쓰기 칸이 있다. 15~20세가 읽고 바로 답할 수 있는 말투인지 본다.
- [ ] 보기 선택만, 직접 쓰기만, 둘 다 섞어서 답할 수 있다. 여러 개 고르는 질문은 "여러 개 골라도 돼요"라고 나온다. 숫자 키로 보기가 골라진다.
- [ ] 답하면 위쪽 질문 워크플로우에 질문/답이 대화처럼 쌓이고, 오른쪽 "애매한 부분" 점수가 줄며 정해진 항목은 "명확"으로 바뀐다.
- [ ] 같은 항목을 두 번 연속 묻고 나면 다른 항목으로 넘어간다(같은 질문이 반복되지 않는다).
- [ ] "이전"을 누르면 바로 전 질문이 내 답이 채워진 채로 다시 열린다.
- [ ] 최대 8개 질문 뒤(또는 "여기까지로 정리하기") "이대로 정리할까요?" 화면에 한 줄 목표, 결정 표, 아직 정하지 않은 것이 나온다. "질문 하나 더"로 더 물어볼 수 있다(최대 12개). 8개를 넘긴 질문은 진행 표시가 "질문 9"처럼 분모 없이 나온다.
- [ ] 지금 질문에 보기를 고르거나 직접 쓴 뒤 "여기까지로 정리하기"를 누르면, 그 답이 "이대로 정리할까요?"의 결정 표에 들어간다(아무것도 안 고르고 누르면 그 질문은 빠진다).
- [ ] "이대로 정리하기" 뒤 결과 화면에 게임 이름(가제 표시), 한 줄 소개, 이게 뭐냐면 / 비유하자면 / 조금 더 자세히 / 그래서 왜 재밌냐면 / 결정한 것들 / 질문 워크플로우가 보인다.
- [ ] "워크플로우로 열기"를 누르면 `/workflow`로 가서 이 세션이 카드로 그려진다.

### 2. 워크플로우 (http://localhost:3100/workflow)

- [ ] 처음 열면 예시 워크플로우가 점 배경 캔버스에 카드와 연결선으로 보인다. 확대/축소, 전체 보기, 미니맵, 캔버스 끌어서 이동이 된다.
- [ ] 카드마다 상태(진행중/동결/취소), 타이틀, 설명, 동결·취소(되돌리기) 버튼, 펼치기 버튼이 있다.
- [ ] 카드를 끌어 옮기고 새로 고쳐도 위치가 그대로다.
- [ ] 연결선 끝에 화살표가 있어 어느 카드로 이어지는지 보인다. 진행중 카드로 들어가는 선과 화살표는 강조색이다.
- [ ] 카드 오른쪽 점에서 다른 카드 왼쪽 점으로 끌면 연결선이 생기고, 선을 클릭한 뒤 Delete(또는 "연결 삭제")로 지워진다. 새로 고쳐도 유지된다.
- [ ] 카드를 펼치면 에이전트 대화 세션(에이전트/내 말풍선, 시간)이 보이고, 아래 입력칸에 메시지를 보내면 에이전트 답이 붙는다.
- [ ] 보내고 기다리는 동안 "답을 쓰고 예시 이미지를 만드는 중이에요."가 보인다. `OPENAI_API_KEY`가 있으면 답에 `예시 이미지:` 한 줄과 함께 새로 만든 그림이 갤러리 첫 타일로 붙는다(답 하나에 한 장). 키가 없거나 OpenAI가 실패하면 그림 없이 답과 참고 링크가 오고, `예시 이미지:` 줄에 이유가 적힌다.
- [ ] 대화 속 URL(에이전트 답과 내가 보낸 메시지 모두)은 "미리보기 N개" 갤러리로 보인다. "슬라이드"/"격자"로 바꿀 수 있고, 슬라이드는 이전/다음 버튼과 "1 / N"이 있다. 이미지 타일을 누르면 크게 보기 창이 열린다. 위키백과 같은 페이지 링크는 제목·썸네일 카드로 나온다.
- [ ] "동결"을 누르면 상태가 동결로 바뀌고 대화를 요약한 "결정"이 카드에 붙으며 입력칸이 잠긴다. "되돌리기"로 다시 진행중이 된다. 진행중 카드의 "취소"는 상태를 취소로 바꾼다.
- [ ] 키보드(Tab, Enter)로 동결, 되돌리기, 취소를 눌러도 포커스가 그 카드의 버튼에 남는다. 입력칸에서 Enter로 보내면 답이 붙은 뒤에도 입력칸에 포커스가 있다. 슬라이드의 이전/다음 버튼은 끝에 닿아도 포커스가 남는다.
- [ ] "카드 추가"로 제목/설명을 넣어 새 카드를 만들 수 있다(제목이 비면 오류 문구).
- [ ] 위쪽 선택 상자로 워크플로우(예시, 질문하기에서 가져온 것)를 바꿀 수 있다.
- [ ] 질문하기에서 가져온 워크플로우는 컨셉 카드 1개 + 답한 질문마다 카드 1개가 차례로 연결되고, 모두 동결 상태이며 결정에 내 답이 들어 있다. 같은 "워크플로우로 열기"를 다시 눌러도 중복으로 만들어지지 않는다. 가져온 카드를 "되돌리기" 후 대화 없이 다시 "동결"하면 결정은 처음 답 그대로다.
- [ ] 동결 카드가 없으면 "기획서 만들기"가 꺼져 있고, 하나 이상이면 눌러서 `/plan`으로 간다.
- [ ] 위쪽 메뉴의 질문하기/워크플로우/기획서가 같은 주소(3100) 안에서 `/`, `/workflow`, `/plan`으로 오간다. 로고는 지금 앱의 첫 화면으로 간다.

### 3. 기획서 (http://localhost:3100/plan)

- [ ] 처음 열면 예시 결정 문서와 예시 이미지 4장이 있고, 골라서 "기획서 만들기"를 누르면 오른쪽에 Markdown 미리보기가 나온다.
- [ ] 기획서는 개요 / 핵심 재미 / 코어 루프 / 주요 시스템 / 아트·분위기 / 결정 로그(표) / 열린 질문/리스크 / 다음 단계 순서다. 결정에 없는 수치나 일정이 지어내져 있지 않은지 본다. 아트 결정은 핵심 재미가 아니라 아트·분위기에 나오고, Step1에서 가져온 콘셉트의 "분위기와 그림체"도 아트·분위기에 들어간다.
- [ ] 아트·분위기 섹션에 고른 이미지가 실제로 보인다(캡션 포함).
- [ ] 미리보기 / 마크다운 / 나란히 탭이 바뀌고, 마크다운 탭에서 원문이 보인다. ".md 다운로드"와 "마크다운 복사"가 된다.
- [ ] 워크플로우의 "기획서 만들기"로 들어오면 "워크플로우에서 결정 N개, 이미지 N개를 가져와 골라 두었어요."가 뜨고 동결 카드의 결정과 대화 속 이미지가 미리 골라져 있다. 새로 고쳐도 중복으로 들어오지 않는다. 워크플로우에서 이미지 타일로 보이던 주소(이미지 확장자로 끝나는 주소, `/workflow/…`·`/plan/…` 이 사이트 이미지, 에이전트가 만든 `/workflow/api/images/<id>`)가 모두 이미지로 들어오고 기획서 미리보기에 보인다.
- [ ] 결정 문서를 수정/삭제하고, 이미지 주소(https)를 추가하거나 PNG/JPEG/WebP/GIF 파일(5MB 이하)을 올려 기획서에 넣을 수 있다. 다른 형식이나 http 주소는 거절된다.
- [ ] "Step1 결과 가져오기"로 질문하기 결과(ELI5 컨셉)를 결정 문서로 가져올 수 있다.
- [ ] '이미지 예시'의 "이미지 만들기"를 열면 고른 결정으로 채운 프롬프트 초안이 보인다(결정을 다 해제하고 열면 비어 있고 안내 문구). 키가 없으면 폼에 `.env.local` 안내가 뜨고 "만들기"가 꺼져 있다. 키가 있으면 "만들기" 뒤 "만드는 중이에요" 문구가 보이고, 만드는 중에는 "닫기"와 "이미지 만들기"가 꺼져 있다. 끝나면 출처 "OpenAI" 타일이 골라진 채로 생기고 키보드 포커스가 그 타일로 가며, 기획서 아트·분위기와 .md 내보내기에 들어간다. 실패하면 입력이 그대로 남고 오류 문구가 뜬다.
- [ ] 폰 너비(390px)에서 아래 고정된 "기획서 만들기"를 누르면, 만들기가 끝난 뒤 화면이 기획서 제목으로 내려가 미리보기가 보인다. 키보드로 누르면 포커스가 기획서 제목으로 간다.
- [ ] Tab/Shift+Tab으로 왼쪽 입력 목록을 오가도 포커스된 버튼이 위쪽 헤더나 아래 "기획서 만들기" 막대에 가려지지 않는다.
- [ ] 미리보기 아래 "저장된 기획서" 목록에서 예전에 만든 기획서를 다시 열 수 있다.

## 알려진 한계

- 사용자 구분이 없는 PoC예요. 로그인은 사이트 전체에 거는 Basic 로그인 하나뿐이고, 들어온 사람은 모두 같은 데이터를 봐요.
- 다른 사이트에서 보낸 쓰기 요청은 브라우저가 붙이는 `Sec-Fetch-Site`로만 가려내요. 이 헤더를 보내지 않는 오래된 브라우저(예: Safari 16.3 이하)에서는 막지 못해요.
- 프록시(3100)는 같은 네트워크의 다른 기기에서도 열려요. OpenAI 키를 넣었다면 그 기기에서도 "이미지 만들기"나 워크플로우 대화로 이미지를 만들어 사용료를 쓸 수 있으니, 믿을 수 있는 네트워크에서만 켜 두거나 `BASIC_AUTH_USER`/`BASIC_AUTH_PASSWORD`를 넣으세요.
- mock 모드의 질문·답변·결정 요약은 키워드 규칙과 정해진 문장이라 아이디어에 따라 어색한 조사나 문장이 나올 수 있어요. 요약 문장에서는 답 속 링크를 빼고 쓰고(링크만 있는 답은 "참고 링크"), 전체 주소는 결정 표에 남아요. 실제 LLM은 응답이 느리고(질문당 수십 초), 규칙에 안 맞으면 mock 질문으로 바뀌어요.
- 워크플로우 에이전트는 키가 있으면 답마다 OpenAI 이미지를 한 장 만들어요. 그래서 답 하나에 수십 초가 더 걸리고 답마다 사용료가 나가요(LLM이 그림이 필요 없다고 하면 만들지 않아요. mock은 늘 만들어요). 다시 만들기나 고르기는 없어요. 이미지 주소의 확장자나 이 사이트 경로로만 이미지를 알아봐서, 확장자 없는 외부 이미지 주소는 페이지 미리보기 카드로 보이고 기획서로 가져오지 않아요.
- 링크 미리보기는 서버가 공개 주소만 가져와요(사설/루프백 IP 차단, 리다이렉트마다 재검사). 막히거나 실패한 링크는 주소만 있는 카드로 보여요.
- 질문하기의 "이전"으로 다시 연 질문에 채워진 답은 브라우저 메모리에만 있어요. 서버에서는 그 답이 이미 지워진 상태라, 새로 고치면 빈 질문으로 보여요("다음 질문"이나 "여기까지로 정리하기"를 누르면 다시 저장돼요).
- 질문하기에서 끝내지 않은 세션은 워크플로우로 가져오지 않아요. 가져온 카드는 모두 동결 상태로 시작해서, 그 카드에서 대화를 이어 가려면 먼저 "되돌리기"를 눌러야 해요.
- 기획서로 가져온 결정·이미지는 사본이에요(기획서 쪽에서 고친 내용을 지키려고). 워크플로우에서 카드를 되돌렸다가 다시 동결해 결정이 바뀌어도 이미 가져온 사본은 그대로고, 다시 가져오면 아직 안 가져온 동결 카드와, 이미 가져온 카드라도 대화에 새로 생긴 이미지 주소가 더해져요. 바뀐 결정을 받으려면 기획서에서 그 항목을 지운 뒤 워크플로우의 "기획서 만들기"로 다시 들어오세요. 같은 방식이라 기획서에서 지운 항목도 다시 가져오면 되살아나요.
- 내려받거나 복사한 .md 속 이 사이트 이미지는 지금 연 주소를 붙인 절대 주소예요(예: `http://localhost:3100/plan/api/images/…`). 그 서버가 켜져 있고 데이터가 남아 있을 때만 보이고(Basic 로그인을 걸었다면 로그인도 필요해요), 다른 곳에 옮기려면 이미지 파일을 따로 챙겨야 해요.
- 질문하기에서 가져온 워크플로우는 한 줄에 카드 4개라, 4번째 카드에서 5번째 카드로 가는 연결선이 다른 카드 뒤를 지나가요. 화살표로 방향은 알 수 있지만 선 일부가 카드에 가려져요.
- 키보드로 카드를 옮기려면 먼저 Enter나 Space로 선택해야 하고, 방향키 한 번에 5px(Shift는 20px)씩 움직여요.
- 워크플로우 카드는 지울 수 없고 연결선만 지울 수 있어요. 동시에 여러 탭에서 고치면 마지막 저장이 이겨요.
- `pocs/frontend`는 화면 시안 참고용 앱이에요. npm workspace에 들어 있지 않고 PoC 실행과는 상관없어요.
