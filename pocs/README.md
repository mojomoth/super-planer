# Super Planer PoC

게임 기획자를 위한 워크플로우 시각화 서비스의 PoC 세 개입니다. Next.js 16(App Router) + SQLite(`node:sqlite`)로 만들었고, 세 앱이 SQLite 파일 하나를 같이 씁니다.

```
질문하기(step1) ──워크플로우로 열기──▶ 워크플로우(workflow-view) ──기획서 만들기──▶ 기획서(plan-doc)
   :3101                                   :3102                                    :3103
```

| PoC | 폴더 | 주소 | 하는 일 |
|---|---|---|---|
| 1. 질문하기 | `step1` | http://localhost:3101 | 대충 쓴 게임 아이디어에 소크라테스식 질문을 하나씩 던지고, 다 답하면 게임 이름(가제)과 ELI5 형식 컨셉을 보여 줘요. |
| 2. 워크플로우 | `workflow-view` | http://localhost:3102 | n8n처럼 카드와 연결선으로 된 캔버스. 카드를 펼치면 에이전트 대화 세션이 보이고, 답변 속 URL은 슬라이드/격자 미리보기로 보여요. |
| 3. 기획서 | `plan-doc` | http://localhost:3103 | 동결된 결정과 이미지 예시를 골라 Markdown 기획서를 만들고, 이미지를 포함한 Markdown 미리보기로 보여 줘요. |

각 앱은 예시 데이터가 들어 있어서 따로 열어도 바로 볼 수 있어요.

## 실행

```bash
cd pocs
npm run dev                         # 세 앱을 한 번에 (3101, 3102, 3103)
npm run dev -w step1                # 하나만
LLM_PROVIDER=mock npm run dev       # LLM 없이 정해진 답으로
```

의존성은 `pocs/node_modules`에 이미 설치돼 있어요. Node 22.5 이상이 필요해요(`node:sqlite`).

### LLM 선택

`lib/llm.ts`가 아래 순서로 고르고, 화면 오른쪽 위에 `LLM: <이름>`으로 보여 줘요.

| 조건 | 사용하는 것 |
|---|---|
| `ANTHROPIC_API_KEY`가 있으면 | Anthropic API (`LLM_MODEL`로 모델 변경) |
| 없으면 | 로컬 `claude` CLI (로그인된 Claude Code 사용, `LLM_CLI_MODEL`, 기본 `sonnet`, `LLM_TIMEOUT_MS`, 기본 120000) |
| `LLM_PROVIDER=mock` | LLM 없이 정해진 질문·답변·문서 조립 |

`LLM_PROVIDER=anthropic|claude-cli|mock`으로 강제할 수 있어요. LLM 호출이 실패하거나 규칙에 안 맞는 답을 주면 자동으로 mock 결과로 대신하고, 화면에 그 사실을 작게 적어 둬요. `LLM_DISABLE_CLI=1`이면 CLI를 건너뛰고 mock으로 가요.

### 데이터

- DB: `pocs/.data/super-planer.db` (WAL). `SUPER_PLANER_DB=/경로/파일.db`로 바꿀 수 있어요.
- 업로드 이미지: `pocs/.data/uploads/`
- 초기화: 서버를 끄고 `rm -rf pocs/.data` 후 다시 실행하면 예시 데이터부터 새로 만들어요.

### 자체 점검

```bash
cd pocs
npm test -w step1 && npm test -w workflow-view && npm test -w plan-doc   # 질문 엔진, URL 추출/미리보기 파서, 기획서 조립
for a in step1 workflow-view plan-doc; do (cd $a && ../node_modules/.bin/tsc --noEmit -p .); done
node ../.claude/skills/hallmark/scripts/sloplint.mjs step1/app            # UI 정적 점검 (앱마다)
```

## HIL 체크리스트

`LLM_PROVIDER=mock`으로 먼저 한 번, 그다음 실제 LLM(CLI 또는 API 키)으로 한 번 해 보는 걸 권해요. LLM을 쓰면 질문 하나에 30초쯤 걸릴 수 있어요.

### 1. 질문하기 (http://localhost:3101)

- [ ] 첫 화면에 아이디어 입력칸, 예시 버튼 4개, 오른쪽에 최근 세션 목록(예시 세션 1개 포함)이 보인다.
- [ ] 세 글자 이하로 보내면 "네 글자 이상 적어 주세요."가 뜬다.
- [ ] 예시 "좀비가 나오는 편의점에서 하룻밤 버티기"로 시작하면 첫 질문이 "…결국 뭘 하는 게임인가요?" 같은 '이 게임은 무엇인가' 질문으로 나온다.
- [ ] 질문마다 한 문장짜리 질문, 쉬운 비유 힌트(게임·폰·SNS·학교 비유), 보기 3~5개, "잘 모르겠어요, 추천해 줘", 직접 쓰기 칸이 있다. 15~20세가 읽고 바로 답할 수 있는 말투인지 본다.
- [ ] 보기 선택만, 직접 쓰기만, 둘 다 섞어서 답할 수 있다. 여러 개 고르는 질문은 "여러 개 골라도 돼요"라고 나온다. 숫자 키로 보기가 골라진다.
- [ ] 답하면 위쪽 질문 워크플로우에 질문/답이 대화처럼 쌓이고, 오른쪽 "애매한 부분" 점수가 줄며 정해진 항목은 "명확"으로 바뀐다.
- [ ] 같은 항목을 두 번 연속 묻고 나면 다른 항목으로 넘어간다(같은 질문이 반복되지 않는다).
- [ ] "이전"을 누르면 바로 전 질문이 내 답이 채워진 채로 다시 열린다.
- [ ] 최대 8개 질문 뒤(또는 "여기까지로 정리하기") "이대로 정리할까요?" 화면에 한 줄 목표, 결정 표, 아직 정하지 않은 것이 나온다. "질문 하나 더"로 더 물어볼 수 있다(최대 12개).
- [ ] "이대로 정리하기" 뒤 결과 화면에 게임 이름(가제 표시), 한 줄 소개, 이게 뭐냐면 / 비유하자면 / 조금 더 자세히 / 그래서 왜 재밌냐면 / 결정한 것들 / 질문 워크플로우가 보인다.
- [ ] "워크플로우로 열기"를 누르면 3102로 가서 이 세션이 카드로 그려진다.

### 2. 워크플로우 (http://localhost:3102)

- [ ] 처음 열면 예시 워크플로우가 점 배경 캔버스에 카드와 연결선으로 보인다. 확대/축소, 전체 보기, 미니맵, 캔버스 끌어서 이동이 된다.
- [ ] 카드마다 상태(진행중/동결/취소), 타이틀, 설명, 동결·취소(되돌리기) 버튼, 펼치기 버튼이 있다.
- [ ] 카드를 끌어 옮기고 새로 고쳐도 위치가 그대로다.
- [ ] 카드 오른쪽 점에서 다른 카드 왼쪽 점으로 끌면 연결선이 생기고, 선을 클릭한 뒤 Delete(또는 "연결 삭제")로 지워진다. 새로 고쳐도 유지된다.
- [ ] 카드를 펼치면 에이전트 대화 세션(에이전트/내 말풍선, 시간)이 보이고, 아래 입력칸에 메시지를 보내면 에이전트 답이 붙는다.
- [ ] 에이전트 답 속 URL은 "미리보기 N개" 갤러리로 보인다. "슬라이드"/"격자"로 바꿀 수 있고, 슬라이드는 이전/다음 버튼과 "1 / N"이 있다. 이미지 타일을 누르면 크게 보기 창이 열린다. 위키백과 같은 페이지 링크는 제목·썸네일 카드로 나온다.
- [ ] "동결"을 누르면 상태가 동결로 바뀌고 대화를 요약한 "결정"이 카드에 붙으며 입력칸이 잠긴다. "되돌리기"로 다시 진행중이 된다. 진행중 카드의 "취소"는 상태를 취소로 바꾼다.
- [ ] "카드 추가"로 제목/설명을 넣어 새 카드를 만들 수 있다(제목이 비면 오류 문구).
- [ ] 위쪽 선택 상자로 워크플로우(예시, 질문하기에서 가져온 것)를 바꿀 수 있다.
- [ ] 질문하기에서 가져온 워크플로우는 컨셉 카드 1개 + 답한 질문마다 카드 1개가 차례로 연결되고, 모두 동결 상태이며 결정에 내 답이 들어 있다. 같은 "워크플로우로 열기"를 다시 눌러도 중복으로 만들어지지 않는다.
- [ ] 동결 카드가 없으면 "기획서 만들기"가 꺼져 있고, 하나 이상이면 눌러서 3103으로 간다.

### 3. 기획서 (http://localhost:3103)

- [ ] 처음 열면 예시 결정 문서와 예시 이미지 4장이 있고, 골라서 "기획서 만들기"를 누르면 오른쪽에 Markdown 미리보기가 나온다.
- [ ] 기획서는 개요 / 핵심 재미 / 코어 루프 / 주요 시스템 / 아트·분위기 / 결정 로그(표) / 열린 질문/리스크 / 다음 단계 순서다. 결정에 없는 수치나 일정이 지어내져 있지 않은지 본다.
- [ ] 아트·분위기 섹션에 고른 이미지가 실제로 보인다(캡션 포함).
- [ ] 미리보기 / 마크다운 / 나란히 탭이 바뀌고, 마크다운 탭에서 원문이 보인다. ".md 다운로드"와 "마크다운 복사"가 된다.
- [ ] 워크플로우의 "기획서 만들기"로 들어오면 "워크플로우에서 결정 N개, 이미지 N개를 가져와 골라 두었어요."가 뜨고 동결 카드의 결정과 대화 속 이미지가 미리 골라져 있다. 새로 고쳐도 중복으로 들어오지 않는다.
- [ ] 결정 문서를 수정/삭제하고, 이미지 주소(https)를 추가하거나 PNG/JPEG/WebP/GIF 파일(5MB 이하)을 올려 기획서에 넣을 수 있다. 다른 형식이나 http 주소는 거절된다.
- [ ] "Step1 결과 가져오기"로 질문하기 결과(ELI5 컨셉)를 결정 문서로 가져올 수 있다.
- [ ] 미리보기 아래 "저장된 기획서" 목록에서 예전에 만든 기획서를 다시 열 수 있다.

## 알려진 한계

- 로그인/권한이 없는 로컬 PoC예요. 앱 사이 이동은 `localhost:3101~3103` 고정 주소예요(다른 포트나 호스트로 띄우면 링크를 고쳐야 해요).
- mock 모드의 질문·답변·결정 요약은 키워드 규칙과 정해진 문장이라 아이디어에 따라 어색한 조사나 문장이 나올 수 있어요. 실제 LLM은 응답이 느리고(질문당 수십 초), 규칙에 안 맞으면 mock 질문으로 바뀌어요.
- 에이전트 답변의 이미지 예시는 picsum.photos 무작위 사진이에요. 실제 이미지 생성은 하지 않아요.
- 링크 미리보기는 서버가 공개 주소만 가져와요(사설/루프백 IP 차단, 리다이렉트마다 재검사). 막히거나 실패한 링크는 주소만 있는 카드로 보여요.
- 질문하기에서 끝내지 않은 세션은 워크플로우로 가져오지 않아요. 한 번 가져온 세션/워크플로우는 다시 가져와도 갱신되지 않아요(기획서 쪽에서 고친 내용을 지키려고). 새로 반영하려면 `.data`를 지우거나 새 세션을 만드세요.
- 워크플로우 카드는 지울 수 없고 연결선만 지울 수 있어요. 동시에 여러 탭에서 고치면 마지막 저장이 이겨요.
- `pocs/frontend`는 화면 시안 참고용 앱이에요. npm workspace에 들어 있지 않고 PoC 실행과는 상관없어요.
